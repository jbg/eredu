# Native consolidation: design and scoped evidence

This document describes the current native mechanisms and the evidence recorded
on 2026-09-18. The [overview](bounded-followup.md) tracks the remaining application
outcomes. Exact commands, binary hashes, timings, failed attempts and zero-test
filters remain in the linked validation records; a passing earlier binary is
not evidence for a later change it did not contain.

## Current design

### Shared numerical and residency workers

Ordinary and admitted layerwise acquisition share one retirement/window worker,
transfer ordering, lease construction and parameter population. Recovery policy
selects either one admitted attempt or ordinary recovery after an actual pending
owner retires. Foreground, dense streamed and background transfers keep their
respective completion guards. Population failure still fences its coordinator.

Each dense window owns its selected group's units. Ordinary acquisition settles
the preceding consumer before trimming to the selected device depth. A group
switch requires exhausted transfers; an early switch preserves the live transfer
and its protections. Persistent source aliases retain their exact exemptions.
Neither a roomy byte budget nor ordinary execution enlarges the selected window.
The disk fixtures distinguish the metadata-only detached catalog, which reports
Memory and zero payload I/O, from the actual reader's physical byte counters.

Host and foreground Disk parameter sources retain the selected CPU or Metal
stream identity. They share the paid manager constructor while quoting distinct
native copy and completion workers. Unloaded slots share the source-derived
scalar/graph constructor census and are replaced before evaluation. Equation
traces authenticate that inventory; sampling remains a separate trace phase.
Immutable source backing, finite attempts and physical capacity remain
independently accounted. The constructor, Host ownership and copy-fact checks exercise these exact
sources. The shared scheduled-completion worker accepts the selected CPU or GPU
source. CPU signal tasks and their records settle before the enclosing bank is
restored; failure retains accepted record and allocation owners. Three native
wrapper checks cover immediate CPU record retirement, actual prepared Metal
streams, escaped-output custody and foreign/lazy/count refusal without attempt
refunds. A separate four-process GPU PP2/EP2 Disk fixture passes ordinary
execution and control; it does not establish admitted three-stream execution.

The block-FP8 Metal kernels share finite definitions, source construction,
shape-derived grids, grouped views and fixed output transport. The catalog has
294 signatures across nine families. Recurrent scans, BF16 projection,
pointwise operations and row reductions use the same approach. Ordinary
high-rank results reshape after the shared kernel; original admission keeps its
exact rank-capacity check. Cold ordinary sources retain their unquoted owner;
paid initialization reserves before source construction. CPU, CUDA and
segmented absorbed-MLA equations retain their distinct mechanisms. Distributed
capture uses the neutral reconstruction plan's logical quota; the former
unexplained 4096-byte surcharge and investigative trace switches are removed.

### Authenticated chat, media and semantic controllers

The portable chat/model-input binding validates the selected execution, exact
tokenizer and actual render, compares every ordered text-token value, then uses
the existing host plan and original model-input compiler. It retains the render,
semantic preparation and immutable part/text coordinates. Equal contents,
caller-provided hashes and arbitrary skip ranges do not confer authority.

Architecture preparation supplies exact render projections on existing semantic
part records. Qwen and Gemma framing follows their processor declarations.
Video extents retain source-group/frame identity and frame-rate bits. The
ordinary processor and original association share the timestamp equation; the
association funds and compares the actual formatted timestamp and encoded
values. It accepts a complete compact or expanded group, never a mixture that
skips unchecked tokens. Native composition only exposes the retained semantic
owner; architecture admission owns expansion and decoder geometry.

Semantic controller admission retains the actual paid history, parser source,
recipe and tokenizer association. It authenticates those owners and their
preparation account independently of native sampling. Only the emitted mask is
priced by the native run. Controller, copy and communication spending remains
cumulative across continuation and branches. Added ByteLevel tokens containing
non-alphabet scalars use the upstream whole-token raw UTF-8 fallback.

### Publication, completion and retirement

A complete initial publication retains scalar receipts for each authenticated
native allocation generation, exact capacity and pool domain. Later publication
observes the real root and revalidates it at attachment commit. An exact live
receipt avoids a duplicate request sidecar on persistent parameter storage.
New allocations, changed descriptors/capacities and foreign domains cannot reuse
that receipt. Empty roots must still be empty. Receipts hold no array or
registration payload and cannot match a later allocation reusing an address.

Lazy Host sources move a sealed successful-publication receipt and their existing
custody into the retained buffer owner. Publication borrows that receipt alongside
the actual native buffer, checks its exact allocation generation and capacity,
and validates the original account in the same pool. Closed healthy accounts
remain valid; foreign or quarantined accounts do not. A rejected source receipt
cannot fall through to an initial receipt. No extra source registry or native
payload pin is created.

Canonical parameter Array cells use the same private scalar proof. Only an
actual successful originating attachment can mint it, after comparing the
registration's metadata payer with the cell's original custody. Initial and
commit observations independently snapshot proof presence and compare fresh
physical facts. A persistent CPU Array therefore keeps its original charge
without retaining a new request account on each use. Its independent Host source
remains separately charged; shared backing still requires exact native evidence.
An unpublished reset cannot overwrite a receipt-bearing cell.

Reset retires a previous enclosing nonstate publication only when every remaining
registration is covered by the still-retained complete initial publication.
Extra original-source custody or uncovered keys prevent retirement. Attached
native, host, metadata and capture aliases retain their independent charges.
Completed media publication visits the actual retained ingress as well as decoder
roots, preserving earlier-span allocation witnesses and their authenticated
completion stream through later state installation.

Explicit synchronous reclamation drains submission, host, ordinary and native
owner queues while actual retirement progresses. Unresolved recovery alone
neither spins nor authorizes release. Synchronization proves stream completion
and session health/idle, drains ready owners, then rechecks expired installed
views that deferred destruction may have invalidated. Runtime-lock, reentrancy,
unwind and panic safeguards remain. Bounded reset and startup do not perform a
global cleanup.

The installed parallel-control projection also has a lexical activation. Cleanup removes only a closed installation after session readiness; live
installations and escaped aliases keep their custody. The seven public native
cases and both factory-source-backed cleanup regressions pass, including repeated
combined TP2/PP2 requests.

Paged Host demotion and return attach the displaced Device reservation to the
two actual native backings before releasing completed internal aliases. A
prepared, thread-affine retirement receiver can destroy only its own completed
callback. Dropping a receiver preserves a live backing and routes its eventual
callback to ordinary reclamation. It never drains unrelated payloads inside a
bounded operation. Completed collector roots retire only after exact descriptor,
scope and positive completion checks; cumulative append debit is not refunded.
Escaped Device aliases therefore keep the same physical charge until final drop.

### Canonical copy and paid reset

Hybrid state uses one grouped copy mechanism for resident and paged sources.
The former all-KV outer-only selector is removed. The grouped worker preserves
layout, global indices, attention arithmetic and fixed offsets. Every actual
child table, including an empty table, has its own funded metadata construction;
zero slot payload is distinct from nonzero header/control storage. Child
publication retains its charge and only the outer table emits prompt completion.
Paged copies retain their exact manager and failure custody.

`ResidentTableResetState` is the canonical reset contract. It checks the actual
component role, allowing Paged attention and Device fixed children in one Hybrid
layer. KV and Hybrid use the same source-authenticated empty-manager constructor.
The final constructor moves the paid context even for a local partition with no
paged attention rows. Reset preserves immutable layout, global indices, child
roles and shared physical pool identity while constructing empty metadata and
tables without numerical copies. Old pages and escaped tensors keep their owners.

Resident, host-layerwise, disk-streamed and distributed adapters use that shared
worker. Preparation checks host and independently admitted communication demand
against one application limit without charging the same physical reservation
twice. Distributed reset agrees `SessionReset` before installation and
`SessionResetPublication` afterward: two cumulative attempts using the existing
two-exchange protocol. Pre-install refusal leaves the old state intact;
post-install disagreement fences session and transport. Reset refunds no prior
capture, copy or transport spending.

### Distributed media and CPU source facts

Observed and unobserved Qwen-VL decoder execution use the same component worker,
so cold and actual collective ranks agree. Media and text execution install the
same retained model/control context around the shared input transaction. The
canonical sum-wave API accepts that context, validates all inputs under its payer
before source entry, constructs all reductions before waiting and completes the
whole wave. Invalid sources retain typed failure custody rather than falling
back to ordinary communication. Placeholder/result/root-reference destinations
and validator transports are priced before allocation.

CPU source facts describe the selected arithmetic, including grouped RMS,
Native YaRN, InputProducts rotary, blockwise attention and Host transfers.
Output readiness is distinct from observer settlement: native fixtures progress
the actual observer, retire its completed record and only then release wrapper
owners. Escaped outputs still keep their payer under the existing deadline.

The CPU broadcast-reshape guard now uses the existing readable stride span and
fixed alias/copy planner. It no longer incorrectly requires repeated logical
broadcast elements to fit the smaller physical backing. Rank, dtype, actual
physical-span and malformed-input refusal checks remain intact.

Grouped CPU projection now honors the explicitly selected F32 tiled worker in
GatherMM. Its source includes all four input owners, typed U32 coordinate
construction, matrix spans and queued index validation. Stable I32 sorting and
axis-zero overwrite scatter use the shared ordinary workers. Nonfinal F32 sums
retain the existing contiguous/strided arithmetic order; sequential reductions
retain broadcast-index gather and ordered additions. Gather validates index
values only after their queued dependencies are ready, and a fixed typed failure
retains submission and output custody until safe retirement. The grouped quote
composes these actual leaves with the existing chunk and observation schedule.
The grouped native leaves pass 32 numerical, parity, refusal and retirement
cases. Their fixed capture slots use the canonical record minimum; production
limits and arithmetic are unchanged.

Completed direct-partition sources retain the exact local bank and member
geometry. Their bounded envelope combines the real equation population with
one residency-copy population, including shared nested workers. Finite row
candidates cover outer tails and inner kernel transitions. CPU and Metal bank,
grouped, static-slice, publication and persistent-Disk regressions pass. The Disk
fixture completes four requests with nonzero full-state/token parity, unchanged
cached parameter identities, exact later-request retirement and final source
retirement. It observes actual initial physical reads and permits warm reuse.

CPU softplus quotes the existing beta-scaled worker, original output precision,
logical Float32 storage floor, Bool/scalar allocations and completion custody.
Typed integer arithmetic quotes the actual zero/multiply/add peer dependency
chain. Empty Broadcast and Full retain their zero-byte Data metadata;
concatenation funds every input and job, including empty blocks. C API validation
checks enum safety and delegates supported scalar types to the native source.

Typed structural aliases preserve integer geometry and the full original source
backing, even when their logical view is empty. Row gathering and additive row
scatter use their existing CPU workers, including empty indices and repeated
row destinations. Selector gathers accept an exact selected-axis width and a
readable strided source; `LogAddExp` uses its own named floating worker. The
earlier pinned 191-patch replay, canonical native archives and these leaves have been
verified: twelve empty/row cases and eight selector cases pass. Frontend
constructor candidates are counted separately from evaluated primitives, input
edges and backing births. Actual Rust composition fixtures pass. The selected-executor artifact passes
seven public tools/media cases and all six distributed CLI modes. Six paged-control
cases pass on the separately recorded runtime-completion artifact.

CPU selector quotation currently qualifies dense F32 operands with one selection
partition, all four scoring transforms, optional input/bias/coefficient
transforms, and exact supplied integer IDs. Joint selection retains the full
partition backing and one shared coefficient allocation. Other configurations
still require their own matching source qualification; a refusal is not an
architectural model limitation.
At the earlier 188-patch checkpoint, all patches replayed from the pinned
archive and the rebuilt native sources passed 11 focused C++ cases: two new cases, eight affected positive regressions and
one exact high-rank CPU Broadcast refusal. That older positive fixture also
failed on the preceding artifact. The corrected refusal fixture preserves its
geometry, supplies the actual physical budget and verifies record retirement.
A pointwise constructor quote does not authorize an unqualified high-rank
pipeline; native guards remain strict.

The source3 backend checkpoint passes all **66 focused cases**, including actual
softplus, integer peers, typed views, checked row movement, both selector workers,
empty slicing, complete constructor inventories and source-funded exclusion
owners. Its final source-role and runtime lookup-frame correction is included.
The later selected-executor artifact passes **seven focused backend cases**,
**seven public prepared-chat cases** and **all six distributed CLI modes**.
Both corrected readiness fixtures also pass native execution, including real
nonzero output, a ready inner event with a live child, bounded timeout custody,
and exact final source-account retirement. Their backend test target uses
optimization level 0 with selected neutral dependencies at level 2; production
code is identical to the optimized matrices. Commands, hashes and both earlier
fixture refusals remain in the native work matrix.

The selected execution mechanism prices only actual group submissions while
retaining the resident parameter registry. CPU indexed execution includes its
four actual parent roots. An inner event becoming ready does not retire the
surrounding native role: bounded completion uses one deadline and keeps unresolved
custody. Routed Resident/Host/Disk now pass their unchanged 120-second deadline
and 64 GiB ceiling, including snapshots, exchanges, reset and capture refusal.
TP2, PP2 and combined TP2/PP2 public media/tools pass at the unchanged 8 GiB ceiling.

The selected-executor build uses Rust optimization level 2 for six packages,
with debug assertions, overflow checks and native development guards preserved.
Its tests use an explicit 64 MiB Rust test-thread stack. Earlier unoptimized
timeouts and admission failures remain in the immutable attempt records; these
passing functional runs are not performance benchmarks.

## Numerical and native C++ evidence

The pinned released Qwen checkpoint at revision
`2fc06364715b967f1860aea9cf38778875588b17` passed prompts of length 5 and 3000,
each followed by three cached decode steps. All eight full 248,320-value rows
were finite, matched reference argmax and had zero violations of

parameter table and validates ordinary fully resident execution, not bounded
admission. Commands, checkpoint provenance, errors and timings are in the
[native numerical record](validation/bounded-followup-native-2026-09-18.json).

The independent InputProducts oracle covers integer positions above 2²⁴ using an
error envelope derived from the pinned SIMD polynomial, phase reduction and F32
operations. A probe checked 38,088 signed rotations and retained sensitivity to

ordinary/paid parity and custody. The oracle probe alone is not evidence of
allocation or completion correctness. Grouped RMS passed eight fresh-process
settlement repetitions; complete CPU assistant and YaRN fixtures also passed.

The broadcast-reshape diagnostic passed three cases and 467 assertions,
including all seventeen recurrence prefixes and three-root completion. The two
permanent reshape tests then passed **250 assertions against the rebuilt

## Reproduction and provenance

Native acceptance uses the pinned Rust 1.98 compiler, `CARGO_INCREMENTAL=0`,
CommandLineTools and the installed MacOSX26.5 SDK, plus a writable
`CLANG_MODULE_CACHE_PATH`. The rustup shim is not qualified evidence. Native
tests use the exact production features and run with Metal access; the filesystem
sandbox reports no device. Large unstripped debug executables can fail in dyld
before `main`, so the recorded runs use separate stripped copies of the same
machine code. No checkpoint or build artifact belongs in tracked source.
Public prepared-chat acceptance uses `RUST_MIN_STACK=67108864` (64 MiB).
After two test-only helper splits, the default 2 MiB debug test stack still
overflows during later recorded child-sampling startup; these passes do not
establish default-stack execution. The [public conformance guide](bounded-followup-public-conformance.md)
records the external frame diagnosis and exact artifacts.
These results cover the recorded Apple Metal/CPU and Ring configurations; they
do not establish unrun CUDA, NCCL or other hardware behavior.

It establishes Array availability as well as transfer-event synchronization,
then verifies exact Host identities, stale-generation refusal, clone/shared-view
