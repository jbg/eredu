# Prospective sampling extension

## Ownership and admission

Original text admission binds an immutable equation program, protected native
storage bank, host controls and finite roles to one reservation. A later sampler
change uses a separate `SamplingExtensionQuote`; it cannot enlarge that original
partition or attach its guard to another account.

`InferenceRequest::begin_sampling_extension` authenticates the actual retained
preparation, core run and policy identities, completed frontier and original
output ceiling. An active prediction, stale or foreign context, or a second
pending update refuses before planning. Its move-only pending owner blocks new
predictions and snapshot/supersession source validation. Abandonment releases
that gate without refunding constructor spending or reusing its issue identity.

`SamplingWorkspacePlanCollector` borrows the actual shared sampler's preparation
and finite step reports before they retire. The plan contains explicit Sampling
phases, with no invented model prefill/decode rows. Composition checks the exact
remaining interval and original planning account. Native providers attach their
actual storage, graph, tracking, work and optional reseed requirements to the same
control and admission workers used for initial text execution.

The admitted extension reuses the existing native storage bank, graph/tracking
capsules and prediction-role bank. It issues only Sampling and SamplingEvent
roles; after commit the old bank continues issuing model, validation and scalar
roles but cannot issue another old sampling role. Every claim still requires the
real active `InferenceTextStep`. Committing a later extension invalidates the
previous extension's future claims without refunding already issued roles or
changing capture budgets or the output ceiling. Native completion and atomic
installation remain backend obligations.

## Original producer funding

Cold native-plan vectors and shared shells, named construction/return controls,
control identities and seal diagnostic strings reserve against the plan's actual
metadata account before their producers. Ordinary and funded policies use the
same workers. Detached native layouts use closed shared-owner retirement; layout
payloads and the shared shell retire before their retained planning account.
Detached seal and control identities also retain the original account.

Sampling host/history peak remains separate from the native tensor contribution.
Replacing the tensor peak with selected physical generations preserves that host
peak once. The extension admits its own account against the same pool and exact
execution identity; no old partition, source registration or spent-role counter
is rewritten.
